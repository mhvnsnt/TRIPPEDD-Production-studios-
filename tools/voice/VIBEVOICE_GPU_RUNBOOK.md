# VibeVoice (Microsoft) — GPU handoff runbook (Wave 6 Worker B)

**Status:** SPEC ONLY — nothing in this file was executed on a GPU in this sandbox.
Do not fabricate audio.

**What it is:** Microsoft Research's long-form multi-speaker TTS research
framework — next-token diffusion over continuous speech latents @ 7.5 Hz;
an LLM understands the script/dialogue flow and a diffusion head renders
acoustic detail. Designed for long multi-speaker scripts (up to ~90 min, up to
4 speakers) — the closest documented match for full Wizard Gang ensemble scenes.

**License / commercial-use read — Worker D, Wave 5** (`docs/VOICE_COMMERCIAL_USE_WAVE5.md` §3):
the code is **MIT** (normally commercial-safe), BUT upstream's README states
VibeVoice is **"limited to research purpose use"** and *"We do not recommend
using VibeVoice in commercial or real-world applications without further testing
and development… intended for research and development purposes only."*
**Worker D's verdict: 🚫 RESEARCH-ONLY.** Two further blockers for production
use: (1) every synthesized file gets an **audible AI disclaimer embedded** plus
an imperceptible provenance watermark — unusable in finished episodes; (2)
voice impersonation without explicit recorded consent is out of scope.
**Research lane only — never load-bearing, never in shipping paths.** If
upstream's stated intent ever changes, re-read the README before re-badging.

**Upstream:** https://github.com/microsoft/VibeVoice (actively maintained into
2026). ⚠️ **2025-09-05: Microsoft removed the VibeVoice-TTS code from the
repository** after misuse was discovered. The long-form multi-speaker TTS
variant **cannot be obtained from upstream anymore**. What remains:
`microsoft/VibeVoice-Realtime-0.5B` (streaming TTS, ~300 ms first-audio latency,
~10 min robust generation) + VibeVoice-ASR models.

## Hardware floor

| Item | Floor | Notes |
|---|---|---|
| GPU (VRAM) | **GPU recommended for real-time** | no official VRAM figure published for Realtime-0.5B; the 0.5B streaming model is the smallest in the family — budget 4–8 GB and measure |
| CPU | **no official CPU story for TTS** | the ASR-BitNet variant runs real-time on CPU (3+ threads) — TTS has no equivalent claim; do not plan CPU TTS |

**What stays blocked without a GPU:** real-time-quality TTS inference.
**What stays blocked WITH a GPU:** the full long-form 90-min/4-speaker TTS —
the code was removed upstream (2025-09-05), so this variant is a **code-availability
blocker**, not a hardware one. Do not chase third-party rehosts for production
use; the research-only verdict covers the whole lane.

## Clone + install recipe

```bash
git clone https://github.com/microsoft/VibeVoice.git
cd VibeVoice
python -m venv ~/venvs/vibevoice-gpu && source ~/venvs/vibevoice-gpu/bin/activate
pip install torch --index-url https://download.pytorch.org/whl/cu126
pip install -e .    # NOTE: this gives you the demo/ASR scaffolding and docs —
                    # the TTS inference code was REMOVED upstream; see below

# Realtime-0.5B weights (still published on HF even though TTS code was pulled)
huggingface-cli download microsoft/VibeVoice-Realtime-0.5B
```

## Inference demo path (research lane)

There is **no official in-repo TTS inference script** since 2025-09-05. The
supported research paths, in order:

1. **The upstream demo notebook** — `demo/vibevoice_realtime_colab.ipynb`
   (follow it on the GPU box; it is the only upstream-blessed path to audio).
2. Community third-party integrations (e.g. Esperanto's `vibevoice` provider) —
   Wave 4 documented the state of a clean clone in
   `tools/voice/PROOFS_WAVE4_TTS.md`; re-verify before relying on any of them.

Test recipe (research-only sanity check):

```python
# shape of the test — exact API depends on which demo path the worker takes
# (upstream notebook is the reference implementation; do not guess one here):
#   input:  one wizard line, e.g. "[S1] The block remembers. [S2] Then let it speak."
#   output: demo/vibevoice_wizard_test.wav
```

**Expected artifact:** a WAV that **audibly says it was generated by AI**
(the embedded disclaimer) and carries the imperceptible provenance watermark.
If the disclaimer is missing, the output did NOT come from the Realtime path —
re-check which model actually ran.

## How the GPU worker verifies success

1. `ffprobe demo/vibevoice_wizard_test.wav` → sane duration, no truncation.
2. Listen: speech is intelligible; **the audible AI disclaimer is present**
   (its presence is the proof of a genuine VibeVoice-Realtime run, not a defect).
3. `nvidia-smi` log: measured first-audio latency (upstream claims ~300 ms for
   the streaming variant — report the measured number) and peak VRAM.
4. Report back: GPU model, which demo path was used (notebook vs third-party +
   exact commit/SHA of anything non-upstream), latency numbers, and an explicit
   statement that the output is **research-lane material only**.

## What stays blocked without a GPU (summary)

TTS inference at real-time quality. More importantly, the **90-minute
4-speaker long-form TTS cannot be recovered from upstream at any hardware
level** — plan the series' ensemble-dialogue lane around Zonos (casting) and
Dia (dialogue scenes), with VibeVoice strictly as an R&D curiosity until
upstream's intent changes.
