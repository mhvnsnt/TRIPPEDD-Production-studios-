# TRIPPEDD Development Library

The production graph is also a development library. Shipping a project creates new evidence and reusable material for the next project.

## Core rule

**Nothing valuable becomes an orphan.**

A finished or abandoned production should leave discoverable links between its ideas, creators, performances, physical sources, editorial versions, generated media, music, locations, props, characters, jokes, and outputs.

## Development objects

- **Idea** — premise, joke, concept, reference, observation, unfinished thought.
- **Format** — sketch, scripted, animation, music, reality, documentary, special, social, interactive, experimental, or a combination.
- **Creator** — writer, performer, director, animator, musician, editor, producer, collaborator.
- **Character** — recurring or one-off fictional/persona identity with appearances and source evidence.
- **Performance** — a recorded or generated performance tied to a person, voice, take, or scene.
- **Asset** — footage, audio, image, model, texture, prop, location, graphic, project file, or generated element.
- **Beat** — comedic/story unit that can be reused, rewritten, reordered, or adapted.
- **Output** — episode, sketch, short, clip, music video, trailer, special, compilation, game/interactivity, or derivative.
- **Derivative candidate** — a machine-suggested future production backed by concrete source references.

## Cross-format reuse

A source may participate in multiple legitimate development paths without duplicating the source itself:

`live-action sketch -> recurring character -> animated short -> social clip -> compilation -> scripted series candidate`

`music performance -> music video -> documentary/profile segment -> live special -> social derivatives`

`reality footage -> documentary assembly -> comedy sketch -> personality short -> promotional package`

`experimental audiovisual material -> themed anthology -> music-driven piece -> title/opening package`

The graph records relationships; it does not automatically publish derivative work.

## Executive-production queries

The studio should eventually answer these from graph evidence:

1. What projects can be advanced using already-approved material?
2. Which characters or performers have enough appearances to justify recurrence?
3. Which unused footage contains strong alternate jokes, reactions, or story beats?
4. Which assets are approved, restricted, expired, or missing provenance?
5. Which concepts can cross formats without creating new infrastructure?
6. Which projects are blocked by a specific human decision rather than automation?
7. Which open-source capability would remove the largest current production bottleneck?
8. What can be packaged into a clip, short, compilation, trailer, special, or longer-form development candidate?

## Evidence rule

A recommendation must carry source references. The AI layer may propose a development opportunity, but it must identify the footage, transcript, asset, character, performance, or prior project that supports the proposal.

## Editorial authority

Reuse suggestions are not automatic greenlights. Human editorial approval remains the authority for story, tone, rights, release, and final publication. Mechanical work should be automated around that decision rather than replacing it.
